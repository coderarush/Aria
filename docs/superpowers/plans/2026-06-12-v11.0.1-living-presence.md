# Aria v11.0.1 — Living Presence Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The blob becomes a full "living presence": on wake she outlines the screen edge as a faint rotating border; when the user finishes talking she consolidates water-like into her blob at a user-draggable, persisted position; while executing multi-step tasks she splashes to the bottom edge and becomes the border again; when done she consolidates back, explains, and dismisses. Simple answers never splash.

**Architecture:** A `PresenceMode` (hidden/border/blob) is derived purely from `IslandViewModel.State` (new `.executing` state added). A new `ScreenBorderView` renders the faint perimeter glow with an organic traveling highlight using testable `BorderMath`. `IslandView` orchestrates choreographed transitions between modes (wake-sweep, consolidate, splash). The blob is draggable via a global mouse monitor that toggles `IslandPanel.ignoresMouseEvents` only while the pointer is over the blob; the position persists as a normalized anchor in `AppSettings`.

**Tech Stack:** Swift 6, SwiftUI (TimelineView/Canvas-free shape rendering), AppKit (NSPanel, NSEvent monitors), XCTest. Build with `make test`; release pinned to `-Onone` (see CLAUDE.md — do NOT change optimization flags).

**Non-negotiables (from CLAUDE.md):**
- Preserve blob brand, wake phrase, all existing behavior. Additive over destructive.
- Border overlay MUST remain click-through except over the blob itself. Never block user clicks — this is the #1 reliability risk in this plan.
- `TimelineView(.animation)` must not run when nothing is visible (idle = zero animation work).
- Audio-thread rule: no @MainActor property access from closures stored in non-actor classes.
- Keep the test suite green (428 tests). TDD for all pure logic.
- Commit per task on branch `aria-v11.0.1`.

## State → Mode mapping (the contract everything implements)

| IslandViewModel.State | PresenceMode | What the user sees |
|---|---|---|
| `.idle` | `.hidden` | Nothing (no border, no blob, no animation ticking) |
| `.listening` | `.border` | Faint blob-like glow rotating around the screen edge |
| `.thinking` | `.blob` | Border consolidates water-like into the blob at saved anchor |
| `.executing` (NEW) | `.border` | Blob splashes to bottom edge → border lights up around screen |
| `.responding` | `.blob` | Border consolidates back to blob; caption explains what she did |
| `.error` | `.blob` | Blob (existing error styling) |

Transitions (choreography):
- `hidden → border` (wake): border fades in 0.45s, highlight sweep starts from the edge point nearest the blob anchor.
- `border → blob` (consolidate, ~0.7s): border width/opacity drain while highlight races to the edge point nearest the anchor; blob scales 0 → 1.12 → 1.0 with a wobble-amp spike (0.25 decaying to baseline 0.07). Reads as liquid pooling into a droplet.
- `blob → border` (splash, ~0.85s total): blob accelerates straight down to the bottom edge (0.35s ease-in, slight vertical squash near impact), then the border ignites from bottom-center spreading both directions around the perimeter (0.5s).
- `blob → hidden`: existing shrink/fade dismiss.
- `border → hidden` (e.g. user cancels while listening): plain 0.3s fade.

Simple vs complex: only the multi-step autonomy path (`AgentOrchestrator.runPlan`) enters `.executing`. Direct conversational answers go `.listening → .thinking → .responding → dismiss` — no splash, no executing border.

```swift
/// How Aria is physically present on screen. Pure mapping from the island
/// state machine so choreography can be unit-tested without rendering.
enum PresenceMode: Equatable {
    case hidden, border, blob

    static func from(state: IslandViewModel.State, visible: Bool, hasSuggestion: Bool) -> PresenceMode {
        guard visible || hasSuggestion else { return .hidden }
        switch state {
        case .idle:       return hasSuggestion ? .blob : .hidden
        case .listening:  return .border
        case .thinking:   return .blob
        case .executing:  return .border
        case .responding: return .blob
        case .error:      return .blob
        }
    }
}
```

### Task 2: BorderMath + ScreenBorderView (design-heavy — Opus)

**Files:**
- Create: `Sources/Aria/UI/BorderMath.swift`
- Create: `Sources/Aria/UI/ScreenBorderView.swift`
- Test: `Tests/AriaTests/BorderMathTests.swift`

**Spec.** The border is a faint, organic glow hugging the screen edge — same brand language as the blob (gradient palette, gooey, alive), NOT a crisp vector stroke. A brighter blob-like mass (the "comet") travels continuously around the perimeter. Must look really faint/ambient — opacity of the base ring ≈ 0.25–0.4, comet peaks ≈ 0.8.

`BorderMath` (pure, TDD):
```swift
enum BorderMath {
    /// Point at parameter u ∈ [0,1) along an inset rounded-rect perimeter
    /// (clockwise from top-center). Also returns the outward normal angle.
    static func point(u: Double, in rect: CGRect, cornerRadius: CGFloat) -> (point: CGPoint, normal: Double)
    /// Perimeter parameter of the edge point nearest to an interior point —
    /// where the consolidate animation drains to and the wake sweep starts.
    static func nearestU(to p: CGPoint, in rect: CGRect, cornerRadius: CGFloat) -> Double
    /// Comet intensity at u for a comet centered at head with given tail length
    /// (wraps around 1.0). 1 at head → 0 at tail end, smoothstep falloff.
    static func cometIntensity(u: Double, head: Double, tail: Double) -> Double
}
```
Required test cases: `point` at u=0 is top-center, u=0.25 right-middle-ish, monotonic progression, all points within rect; `nearestU` for a point near the bottom-center returns ≈ 0.5; `cometIntensity` is 1 at head, 0 beyond tail, handles wrap (head=0.05, u=0.98).

`ScreenBorderView`: TimelineView(.animation)-driven. Renders the inset rounded rect (inset ~7pt, cornerRadius ~26) as: base ring = `RoundedRectangle.strokeBorder` with the palette gradient at low opacity + 6pt blur; comet = a stroked trim segment (or N sampled circles along `BorderMath.point`) with higher opacity + glow, head position `u = (t * 0.08).truncatingRemainder(dividingBy: 1)` (≈12s per lap — slow, calm), tail ≈ 0.18. Subtle organic width modulation using `BlobMath`-style detuned sines (±2pt). Parameters in: `palette: [Color]`, `intensity: Double` (0…1, drives opacity — used by transitions), `sweepPhase: Double?` (nil = full ring; during splash-ignition, only |u − 0.5| ≤ sweepPhase·0.5 is lit, spreading from bottom-center u=0.5).

### Task 4: Draggable blob with persisted anchor (AppKit-tricky — Opus)

**Files:**
- Modify: `Sources/Aria/UI/IslandPanel.swift`
- Modify: `Sources/Aria/UI/IslandView.swift`
- Modify: `Sources/Aria/App/AriaController.swift` (panel wiring only if needed)
- Test: `Tests/AriaTests/BlobHitRegionTests.swift` (pure rect math)

**Spec.** The user can drag the blob anywhere; the normalized position persists to `AppSettings.orbAnchor`; consolidation targets it from then on.

Mechanism (single full-screen panel preserved):
1. `IslandPanel` gains `var interactiveRegion: CGRect?` (screen coords, set by the SwiftUI layer via a preference/callback reporting the blob's current frame, inflated by 12pt).
2. A local + global `NSEvent` mouse-moved monitor (installed ONLY while PresenceMode == .blob, removed otherwise — keep it cheap) compares the cursor to `interactiveRegion` and toggles `panel.ignoresMouseEvents` accordingly (false over blob, true elsewhere). While a drag is in flight, keep it false until mouse-up.
3. Blob gets a `DragGesture(minimumDistance: 4)` — updates a live offset while dragging (blob follows finger 1:1, slight scale-up 1.05 + amp boost while held, feels alive), on end converts final center to normalized `CGPoint(x: x/screenW, y: y/screenH)`, clamps to [0.06, 0.94] both axes, writes `AppSettings.shared.orbAnchor`.
4. **Safety invariant (the reliability-critical part):** `ignoresMouseEvents` MUST return to `true` whenever mode ≠ .blob, on dismiss, on monitor teardown, and in `deinit`/app-will-terminate. Centralize in one method `syncInteractivity(mode:cursorInRegion:)` so there is a single writer. Pure-math test: extract `BlobHitRegion.contains(cursor:blobFrame:inflation:)` and the clamp logic into a small enum and unit-test it.
5. Dragging only in `.blob` phase — never during border/transition phases.

Mouse-moved global monitors need no special permissions (only key events do). Use `NSEvent.addGlobalMonitorForEvents(matching: [.mouseMoved])` + `addLocalMonitorForEvents`; store tokens, remove on teardown.
